# Execution controls

The canonical census evaluates the unmodified public checkpoint on CUDA with
one native-horizon input at a time, resetting state before each forward. The
public readout sums softmax probabilities across output bins. Neither the
batch-256 benchmark nor a CPU replay replaces this definition.

## Recompute the retained results

```bash
python -m ssc_geometry execution-controls --out outputs/execution_01
```

The command prints its five phases, validates source IDs, input hashes, horizons,
contracts, scores and candidate coordinates, and writes full-precision tables.
It reads the included arrays and executes no neural-network forwards.

## Padding

The public readout includes all padded output bins. Extra bins contribute
softmax mass, and padding can also change processing inside the valid prefix.
The recorded 408-source diagnostic contains the 344 padding-sensitive sources
and 64 unchanged controls. Removing only the extra output contributions restores
26 changed labels; 318 remain different through the prefix computation.

Zero-padded inputs can acquire nonzero activity after normalization and neuronal
processing. Attention and the symmetric 31-tap local convolution provide
possible routes into valid positions; their separate contributions have not
been isolated. The recorded attention mask removes invalid key columns of the
attention product before multiplication by values; it does not mask all q/k
LIF states, local convolution, or the public readout.

The full-validation arrays permit a direct padding-gap description:

The association is descriptive. The prefix ablation has its original summary
and executed code in this repository, but its complete per-source diagnostic
arrays are not bundled; it is not regenerated by the array-only command.

## Q/k source isolation

The pinned attention implementation sends its q/k tensors through a raw
reshape before the second LIF stages. Logical source ownership then crosses
membrane lanes: the recorded `T=200, B=256, N=256` layout has multiple sources
in every lane. The diagnostic wrapper undoes that storage layout, evaluates
each source with exactly the public singleton head/time convention, and restores
the caller's output layout. Both `q_lif2` and `k_lif2` are isolated in both blocks.

Within fixed batch shapes, this intervention eliminates all original order
effects: **every one of the 9,981 isolated score vectors is bitwise invariant
under reversal**. Three recorded `[x,y]`, `[y,x]`, `[x,x]` pair controls also lose
their position and order effects under joint isolation. Single-branch ablations
retain effects. The singleton bypass preserves its definition; the batch
comparisons provide the evidence for the intervention.

Against padding-matched singleton execution, isolated batching reproduces
9,980 labels. The sole residual source is 7942: class 27 becomes its true class
25. Full score equivalence does not follow:

| Per-source maximum absolute score difference | Median | 95th percentile | Maximum | Sources above 1e-4 |
| --- | --- | --- | --- | --- |
| Isolated batch vs padded singleton | 1.90735e-6 | 3.81470e-6 | **3.71360** | 54 |
| CPU vs CUDA native singleton | 1.90735e-6 | 3.81470e-6 | **3.05130** | 134 |

The 1.91e-6 maximum in the three pair controls is a different, smaller cohort.
It must not be used as the maximum for full validation. CPU/CUDA native
singleton labels differ only at source IDs 7368 and 7558; all 100 canonical
panel CUDA score vectors reproduce the original clean vectors bitwise.

The weights were trained on the public coupled batch-256 path. The source
isolated diagnostic changes batched execution while retaining singleton
processing. A conventional head/time permutation would define a third
function; these weights were not optimized for it and it was not evaluated.
The results concern this pinned implementation and checkpoint. They do not
establish which execution path produced other authors' published results.

## Device persistence of class-changing neighbors

The device control replays exactly the original 5,157 adverse, 9,031 corrective
and 11,632 lateral candidates, each with native-horizon singleton execution.
Q/k isolation is disabled for these replays.

- CPU/CUDA predicted labels agree on **25,794 / 25,820**, or **99.8993%**.
- Transition types agree on **25,795 / 25,820**, or **99.9032%**.
- Fresh CUDA labels and transition types match the original canonical outcomes
  for every replayed candidate.
- Both devices recover the same 13 adverse-sensitive sources and retain each
  source's first canonical adverse witness.

Twenty-five CPU transitions return to the clean class. The remaining label
disagreement changes an adverse candidate's wrong target but retains its adverse
type. The control does not replay the 699,250 originally preserved candidates,
so it does not measure new adverse incidence outside the selected cohort.

## Run provenance

The run contracts record PyTorch 2.11.0+cu128, CUDA 12.8, cuDNN 91900, the pinned
dependency wheels and the actual CPU/GPU hardware. Original JSON contracts,
summaries and executed source bytes are preserved. The compact verification
code is separate from the historical Colab/Drive launchers; see
