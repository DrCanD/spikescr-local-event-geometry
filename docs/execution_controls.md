# Execution controls (Appendix A)

The canonical census evaluates the unmodified public checkpoint on CUDA, one native-horizon input at a time, with a
state reset before each forward and the public time-summed softmax readout. Neither the batch-256 benchmark nor a CPU
replay replaces this definition; the controls below measure how far each other execution condition departs from it.

```bash
python -m ssc_geometry execution --out outputs/execution      # Tables 2, A.1, A.2, A.3 from the retained arrays
```

## A.2 Padding

The public readout sums every padded output bin, so padding adds softmax mass and can also change the processing of
the valid prefix (Eq. A.1 of the manuscript). On the full validation set the label-change rate grows with the number
of added bins:

| Added bins | Sources | Changed | Rate |
| --- | --- | --- | --- |
| 0 | 4,057 | 0 | 0.00% |
| 1–5 | 5,004 | 236 | 4.72% |
| 6–10 | 45 | 2 | 4.44% |
| 11–20 | 155 | 13 | 8.39% |
| 21–40 | 294 | 26 | 8.84% |
| 41–80 | 322 | 43 | 13.35% |
| 81 or more | 104 | 24 | 23.08% |

The decomposition run re-executed the 344 padding-changed sources and 64 unchanged positive-padding controls:
removing only the added-bin output restores 26 labels, 318 remain changed through the valid prefix alone, and
adding the observed extra output to the fixed native output changes 43 labels. These values are read from
`data/execution/summary.json`; the per-source arrays are regenerated by `scripts/run_execution_controls.py --step padding`.
Zero input at a padded position does not guarantee zero downstream activity after normalisation and stateful
spiking; the attention mask excludes invalid key columns from the attention product but not the q/k LIF states, the
local convolution or the readout. No branch-specific padding intervention was performed.

## A.3 Source isolation in the q/k LIF layout

In the pinned attention code the rotary-encoded queries and keys are contiguous in `[B, h, T, d]` and are reshaped
to `[T, B, N]` before `q_lif2` / `k_lif2`. In a batch, each of the `B·N` membrane lanes therefore receives entries of
`T` different sources along its declared time axis (65,536 lanes × 200 sources in the `T=200, B=256, N=256` group),
and reversing the batch order changes those sequences. The diagnostic wrapper (`ssc_geometry.forward.qk_isolation`,
Eq. A.2) gives every source its own LIF sequence with exactly the public singleton head/time convention and returns
the caller's layout; singleton inputs bypass it, so the audit path is unchanged.

- Every one of the 9,981 jointly isolated score vectors is bitwise invariant under batch reversal; q-only and k-only
  isolation retain order effects. The three `[x,y]`, `[y,x]`, `[x,x]` pair controls lose their position and order
  effects under joint isolation (maximum difference from the padded singleton 1.91e-6 in that small cohort).
- Against the padding-matched singleton, isolated batching reproduces 9,980 labels; source 7942 changes from class 27
  to its true class 25. Score equivalence does not follow: the per-source maximum absolute score difference has
  median 1.91e-6, 95th percentile 3.81e-6 and maximum **3.7136**, with 54 sources above 1e-4.
- CPU and GPU native singletons differ on sources 7368 and 7558 only; all 100 panel GPU score vectors reproduce the
  clean vectors bitwise.

The checkpoint was trained on the coupled batch-256 path, so its weights belong to that function. Source isolation is
a diagnostic that keeps singleton processing; a conventional head/time permutation would define a third function that
was neither optimised nor evaluated. The results concern this pinned implementation and checkpoint.

## A.4 Device replay of the class-changing candidates

The 5,157 adverse, 9,031 corrective and 11,632 lateral candidates were re-executed once on the CPU and once on the GPU
as native-horizon singletons (q/k isolation off).

| Canonical type | Candidates | CPU same type | CPU same class |
| --- | --- | --- | --- |
| Adverse | 5,157 | 5,152 | 5,151 |
| Corrective | 9,031 | 9,022 | 9,022 |
| Lateral | 11,632 | 11,621 | 11,621 |
| Total | 25,820 | 25,795 | 25,794 |

The GPU retains every canonical type and class. The 25 CPU type disagreements are returns to the clean class; one more
adverse candidate changes its wrong target but stays adverse. Both devices recover the same 13 adverse-sensitive
sources and each source's first canonical adverse witness. The per-candidate maximum absolute CPU/GPU score difference
has median 1.43e-6, 95th percentile 2.86e-6 and maximum 1.1871. The 699,250 originally class-preserved candidates were
not replayed, so adverse incidence outside the selected cohort is not estimated here.

## Provenance

The contracts of the two control runs are `provenance/contracts/execution_gpu_conditions.json` and
`provenance/contracts/execution_isolation_and_replay.json` (PyTorch 2.11.0+cu128, CUDA 12.8, cuDNN 91900, the pinned
wheels, the CPU and GPU hardware); their hashes are stored inside the output arrays and checked by `execution`. The
hashes of the executed scripts are in `provenance/records.json`; `scripts/run_execution_controls.py` implements the
same procedures with repository-relative inputs.
